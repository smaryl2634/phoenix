# 不死鸟 Phoenix 长任务使用指南

不死鸟不再自己提供"启动长任务"的命令——长任务本身用 Hermes 官方原生的 `/goal`
功能，不死鸟只是在这基础上加了两条安全规则。

## 怎么用原生 `/goal`

在交互式 `hermes chat` 会话里：

```
/goal <你的目标，用自然语言描述>
```

**注意：只能在交互式会话里用，`hermes chat -q "/goal ..."` 这种一次性命令模式不行**——
真机测试过，`-q` 模式不解析斜杠命令，会把整句话当成普通聊天内容发给模型，`/goal`
不会真的被设置。

设置后，Hermes 会在每轮对话结束后自动判断目标有没有完成：

- 没完成 → 自动把"继续朝这个目标努力"的提示喂回给模型，同一个会话继续跑，不用你
  每次手动催
- 完成了 → 自动停止，告诉你完成了
- 卡在等待某个后台任务（比如构建、部署）→ 智能暂停，不浪费轮次预算，后台任务一
  结束自动继续
- 达到轮次上限（默认 20 轮）→ 自动暂停，提示你 `/goal resume` 决定要不要继续

其他常用命令：

```
/goal status          # 查看当前目标进度
/goal pause           # 手动暂停
/goal resume          # 恢复
/goal clear           # 清除当前目标
/subgoal <条件>        # 中途给目标追加一条必须同时满足的条件
```

## 不死鸟在这基础上加了什么

`/goal` 激活期间，不死鸟额外加两条安全规则：

1. **清单强制**：目标激活后，除了 `todo`/`memory`/`session_search` 这几个不产生
   外部副作用的工具，其他工具调用会被拦住，要求模型先用 `todo` 工具列出具体步骤
   清单，再继续干活——防止模型跳过规划直接动手。
2. **高危操作换模型复核**：长任务模式下没有人实时盯着，深度/真神档位（生产环境/
   数据库/安全类操作）不会像正常交互那样弹出人工确认——不死鸟会要求模型委派一个
   使用不同模型的评判子 Agent 先复核这个操作该不该做，复核通过才放行。

这两条规则不需要你额外配置，`/goal` 一旦激活就会自动生效；`/goal` 结束或清除后
自动失效。

## 查看状态

`hermes phoenix-status` 里的"长任务(Loop)"这一行只会提示你用 `/goal status` 查——
不死鸟自己拿不到具体的目标进度（这是两个独立系统，不死鸟只负责在 `/goal` 激活时
加规则，不负责展示 `/goal` 自己的状态）。
